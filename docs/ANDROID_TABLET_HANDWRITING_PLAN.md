# 手写白板优化与后续客户端迁移方案

状态：方案草案，尚未实施。现在先改进现有 Web 白板；以后产品做成客户端，手写编辑仅面向 Android 平板，电脑和 Android 手机查看手写内容。

## 目标

- 让当前白板的日常书写更自然、稳定，现阶段就能获得改善。
- 优先处理点画、短笔画、压感、笔迹跟手和橡皮，不增加复杂笔刷或冗余界面文案。
- 保留现有笔记及外观，逐步分离可复用的输入、笔刷和数据逻辑，为未来客户端适配创造条件。
- 不在本阶段开发 Android 客户端或原生原型；不假定以后一定采用某种客户端框架或手写引擎。

## 现状与边界

当前白板位于 `frontend/src/components/WhiteboardCanvas.vue`，使用 Pointer Events、Canvas 和 perfect-freehand；已有书写实时层、完成笔迹层和路径缓存。`frontend/src/whiteboard/payload.ts` 可以读取 v1、v2、v3 数据，目前以 v3 JSON 保存。后端 `backend/app/routers/notes.py` 将白板正文作为 JSON 存储。

现有应用可以在电脑上测试鼠标和支持的手写笔输入，但最终 Android 平板手写体验取决于设备、笔和客户端运行环境；没有目标设备实测前，不预设跟手程度。

## 第一阶段：在现有白板上改善笔触

### 1. 建立基线

- 收集固定的测试笔迹：中文小字、点画、短横竖、英文、公式、快速转折和长笔画，覆盖鼠标与可用的手写笔。
- 检查书写中、抬笔后、保存重开和缩放后的显示，记录现有问题。保留 v1/v2/v3 样本以及带图片、多页、擦除后的笔记用于回归。
- 有真实平板或笔时记录型号和测试结果；没有时先完成浏览器与可用设备测试，标明实机验证尚未完成。

### 2. 改善输入与笔迹

- 正确保存单点和短笔画，检查首尾采样与抬笔后的笔迹形状，减少跳变和断线。
- 在环境支持时读取合并指针采样，兼容不支持该能力的环境；评估现有小距离过滤对小字、转折和压感的影响。
- 手写笔有可用压感时保留实际压感；鼠标和无压感设备使用稳定回退。区分真实压感和模拟压感，不假定所有设备数据相同。
- 保持书写实时层和完成笔迹的关键参数一致，并在长笔画测试下检查性能；预测采样暂不作为必需，若后续使用，只用于临时显示，不保存预测点。
- 初步调好圆珠笔、钢笔、荧光笔三个现有工具：圆珠笔粗细稳定，钢笔压感自然，荧光笔宽度和透明度稳定。先调整默认值，不增加复杂设置面板。

### 3. 确保橡皮与基本操作可靠

- 验证鼠标、手写笔及模拟触摸的拖擦，局部擦除只影响经过的范围，整笔擦除命中后删除整笔。
- 检查撤销、重做、跨页切换、缩放、保存重开及擦除后继续书写。保留现有图片和页面内容。
- 通过实际事件和画面检查验证交互；几何函数测试不能代替真实拖动测试。

### 第一阶段验收

- 点画、短线、连续笔画可写入，书写中与抬笔后没有明显不合理变化；保存重开和缩放后仍一致。
- 橡皮能够连续拖擦，撤销/重做及保存重开结果正确；自动保存或切换笔记不会静默丢失修改。
- 固定笔迹和旧版本样本回归通过；现有笔记、图片、多页及纸张信息不丢失。
- 前端构建通过，浏览器执行实际拖动测试；未覆盖的平板和手写笔型号单独注明。

## 第二阶段：整理可复用逻辑与格式

1. 以小步方式把采样处理、笔刷参数及笔迹数据逻辑从 Vue 组件中拆到可独立调用的模块；保持现有页面行为，避免为了架构而整体重写。
2. 明确页面坐标、采样点、压感、笔刷类型与参数的含义，并为新笔迹记录笔刷算法版本。旧笔迹沿用旧渲染规则，避免仅因默认笔刷调整而改变已有内容；先验证再迁移，保留原始数据。
3. 区分平台无关部分与浏览器绑定部分。TypeScript 计算和数据处理在未来同技术栈客户端中可能复用；DOM 事件、Canvas 以及浏览器 API 需要按实际客户端环境验证或适配。
4. 将保存、重载、旧版兼容、不同缩放以及擦除后的样本作为回归基线，避免跨阶段破坏数据。

完成标准：旧笔记仍可读写且外观保持；新旧版本识别明确；抽离模块有实际调用方和必要验证，不影响现有功能。

## 第三阶段：未来客户端适配

- 确定客户端技术后再选择实现：若沿用现有前端运行环境，优先复用现有模块；若 Android 平板手写改用原生 Ink，则评估 TypeScript 逻辑重用方式、笔迹格式转换和渲染差异，不能假定直接迁移。
- 先以旧笔记副本试验转换，覆盖多页、图片、各种笔刷与擦除切段；未经验证不得覆盖原件。验证失败时保留可查看路径。
- 平板保留可编辑笔迹数据。电脑和 Android 手机只读查看；页面预览可作为候选方案，但要绑定正确的笔记版本，并与正文采用一致的访问和备份策略。
- 客户端之间的数据传递、离线修改和冲突处理须另行设计；目前不能假定已有跨设备同步。
- 在目标 Android 平板和手写笔上测试压感、跟手、误触、缩放和长时间书写，再决定是否需要原生输入或渲染优化。

## 暂缓

现在不开发平板原生原型，也不把复杂纹理笔刷、字迹美化、OCR、手写搜索或实时协作作为基础笔触优化的前置条件。
