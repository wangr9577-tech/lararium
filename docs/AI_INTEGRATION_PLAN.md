# Kruskal 全站 AI 融合改造建议

日期：2026-11-12。状态：基于当前源码的设计建议，尚未实现，也不代表所有建议已获用户确认。

## 1. 改造目标

让 Kruskal 帮用户把事情推进下去：减少信息搬运、安排决策、重新进入工作状态和事后整理的成本。

以一个连续流程组织现有功能：

**随手收集 → 理解与关联 → 提出安排 → 带着资料开始工作 → 记录产出 → 调整下一步。**

AI 既需要回答问题，也需要在具体页面给出可直接使用的结果。全局助手负责跨模块协调，页面内的轻量操作负责当前工作，两者共享上下文和执行能力。

## 2. 当前代码提供了什么

本轮只静态审阅源码，没有调用真实模型或读取个人正文；以下不能视为运行效果验证。

| 位置 | 已有基础 | 当前缺口 |
| --- | --- | --- |
| 首页 `frontend/src/views/Dashboard.vue` | 今日待办数、专注时长、笔记和论文数量、功能入口 | 没有今日重点、安排建议或继续上次工作的入口 |
| 全局布局 `frontend/src/layout/AppShell.vue` | 全局随手记、快捷键 | 没有带当前页面上下文的常驻 AI 面板 |
| 随手记 `frontend/src/components/QuickCaptureModal.vue` | 速记卡片、智能助手、今日安排三个投递目标，支持截图 | 用户仍需先选择存放位置；理解与后续处理分散 |
| 助手 `backend/app/routers/assistant.py` | 通知研判、来源合并、截止日期与任务联动、笔记草稿、有据问答、后台处理 | 综合问答上下文主要取最近 6 个活跃事项和最近 6 个收集记录；没有接入全站笔记、论文、日程和专注记录的检索 |
| 论文 `PaperReader.vue`、`routers/ai.py`、`services/paper_translate.py` | 论文摘要、阅读器翻译、后台全文翻译队列 | 摘要接口按抽取文本的前 18000 字符处理；尚未形成按问题检索页码、跨论文比较、转为自己笔记的连续流程 |
| 笔记 `NoteEdit.vue`、`NoteView.vue` | 编辑、自动保存、关联资料；助手来源可带入笔记草稿 | 缺少基于选中文字的解释、改写、补证据和复习操作 |
| 日程、时间表、四象限、番茄钟 | 日程已有优先级和估时；专注数据已有部分日程关联；四象限保存在浏览器 | 关联有限；四象限独立文字不是后端可直接读取的任务；时间表主要是自由文字，不能直接当作精确忙闲数据 |
| 模型服务 `backend/app/services/llm.py` | 统一调用、模型配置、结构化结果、流式输出、多模态辅助 | 需要在调用之上增加统一检索、动作执行和后台工作调度 |

路由已把 `/lab` 重定向到首页。本方案围绕现有页面和任务增加关联，不以恢复已下线工作台为前提。旧文档中与当前路由冲突的设计不能直接作为现状。

## 3. 优先贯通的日常体验

### 3.1 首页：给出今天的行动选择

首页保留必要统计，把主要空间用于：

- **今日重点**：最多 3 件事；每件显示推荐原因、预计投入、相关截止时间和来源。
- **继续上次**：最近处理的任务、关联资料、最后一次进展、下一步入口。
- **需要处理**：临近截止、安排冲突、尚未处理的通知；先呈现最相关的少量条目。
- **一句话安排**：例如“下午只有两小时，优先推进组会准备”。

建议必须解释依据，例如“这项任务明天截止，当前估时 90 分钟”；没有截止时间、估时或进展记录时，明确显示缺项。不能仅凭最近打开过就断言它最重要。

用户可把任务固定为今日重点，AI 后续调整尊重固定项。数据未变化时复用结果，不在每次打开首页时重新请求模型。

### 3.2 随手收集：先存下来，再处理

保留手动投递方式，增加一个默认可用的“先收集”入口。用户粘贴文字、链接或截图后先可靠保存，随后异步提出：

- 这是通知、想法、阅读材料、生活记录，还是待确认的内容？
- 原文是否明确包含待办、日期、金额？对应原句在哪里？
- 是否与已有任务或资料有关？可能重复哪一条？
- 可以执行哪些后续动作：关联任务、存成笔记、加入日程、保留为未分类？

日期有歧义时保留歧义。仅有 URL 而未成功读取网页时，只能根据 URL、用户备注及已获取内容处理，不能声称读过全文。

减少多次确认：用户可勾选一组建议后一次应用；也可直接说“记下明天 15 点开会”，由该明确指令直接创建并返回结果和撤销入口。

### 3.3 任务：从一个标题扩展为可继续工作的入口

在现有任务上增加可展开的详情区域，不增加另一套必须维护的任务系统：

- 我想完成什么：可选的成果描述。
- 下一步：AI 建议的一个具体动作，用户可以直接修改。
- 相关资料：现有论文、笔记、通知、速记的引用。
- 最近进展：用户补充的简短记录，以及实际关联的工作产出。
- 操作：“拆成几个步骤”“找相关资料”“开始专注”“记下进展”。

例如“准备组会”可建议先确认讲述问题、选择结果图、整理 5 页提纲；这些是建议步骤，不冒充已安排的任务。没有明确需要时，步骤只留在详情里，避免把日程拆成几十个小任务。

跨天持续的工作可以按需加一个轻量主题标签或关联集合；先验证任务详情是否足够，再考虑独立的长期目标页面。

### 3.4 论文、笔记与白板：围绕正在做的内容提供帮助

**论文阅读：**

- 划选一段后，解释这一段、符号或方法；答案链接回具体页码和片段。
- 带着当前任务提问：“这篇论文对我的组会有哪些可用内容？”用户可编辑任务关联。
- 选几篇已有论文，比较研究问题、方法、实验条件和局限；缺少原文的信息留空或标注未找到。
- 阅读后生成带引用的笔记草稿，并关联原论文；保留用户自己的批注。

**笔记写作：**

- 选中文字后解释、精简、改写或翻译；展示修改预览，再应用到选区。
- 按当前主题寻找站内相关笔记与论文，把可用段落和引用放在侧栏。
- 从已有材料整理提纲，提示论证缺口；没有证据的结论标为待补充。
- 把选定内容变成问答卡、回忆题和复习摘要。

**白板与课件：**

- 用户选择页面或区域后，识别文字、解释公式、整理提纲、生成练习题。
- 识别结果与原页并排，允许纠正手写识别错误；需要模型具有图像能力或接入 OCR。
- 这部分独立于实时书写链路，不需要先完成旧文档中的 AI 笔迹美化计划。

### 3.5 番茄钟：缩短开始工作的准备时间

从任务点击“开始专注”，自动带入任务及关联资料；计时开始前只展示本次想完成的一件小事。

结束时可选填一句“完成了什么／卡在哪里”，AI 据此建议下一步，并提供关联本次笔记或阅读材料的入口。不在每个番茄结束时强制聊天。

区分三种事实：投入时间、任务勾选、真实产出。25 分钟计时只证明记录了这段投入，不能直接标记论文已读完或任务已完成。

### 3.6 复盘：由实际记录形成可修改草稿

晚间或周末按需生成：完成了什么、留下哪些产出、哪些安排未完成、下一步可怎样调整。

工作复盘主要读取任务状态、关联笔记、专注记录和用户进展；生活日记仍保留个人叙述，两者可以分开或由用户选择合并。资料覆盖不足时说明范围，不能把未记录推断成未工作。

用户采纳的调整可以更新次日计划；未采纳的建议不会自动变成任务。

## 4. 其他页面怎样接入

| 页面 | 值得加入的 AI 行为 | 阶段 |
| --- | --- | --- |
| 日程与四象限 | 从自然语言填写字段；解释优先级建议；在约束下提出时间块；未完成事项提出延期、拆分或取消选项 | 第一阶段起 |
| 生词本与雅思 | 用自己的阅读材料生成例句和小测；根据错题建议复习；作文批改展示理由与改写对照 | 后续 |
| 钱包 | 一句话记账、截图提取金额和类别、解释统计中的变化；金额汇总继续由确定性代码计算 | 后续、按需 |
| 时光机、相册 | 为用户选中的内容建议标题、标签与回忆草稿；和相关日期的日记建立可选关联 | 后续、按需 |
| 个人主页 | 从用户选定的真实笔记和成果整理简介、CV 条目草稿，保留编辑和发布流程 | 后续、按需 |
| 设置 | 选择哪些资料可用于 AI、主动建议频率、调用预算；查看后台任务、失败与取消状态 | 共用基础 |

全站融合强调共享信息和连续操作，不要求每个页面都显示同样的聊天窗口。高频工作先做深，低频功能可以逐步覆盖。

## 5. 共用界面：一个入口，多种工作结果

在全局布局增加可收起的助手侧栏。它默认知道当前页面的对象 ID、用户主动选择的文字和当前任务，不扫描浏览器之外的内容。

侧栏的输出按工作类型展示：

- 问答：简短答案、来源、可继续的操作。
- 安排：待办和时间块预览，可勾选应用。
- 改写：原文与候选修改，应用选区或另存草稿。
- 检索：资料列表、匹配片段、为什么相关。

编辑页即使隐藏顶栏，也能从编辑工具栏打开助手；窄屏改为抽屉。侧栏可关闭，普通编辑、阅读和计时始终可单独使用。

现有 `/assistant` 保留为收集记录与处理历史页；与全局面板调用同一组能力，逐步避免同一个功能出现两套逻辑。

## 6. 实现所需的四层能力

### 6.1 统一上下文与引用

为笔记、论文、通知、日程、专注等增加小型读取适配器，返回统一引用：对象类型、ID、标题、定位信息、内容版本。数据仍留在原有模块。

新增轻量关联层，按需表达“任务使用这篇论文”“本次专注属于这个任务”“这篇笔记是这次工作的产出”。复用已有日程 ID、专注关联和助手关联，避免重建重复记录。

日记、钱包等内容不默认进入所有回答；使用范围应在具体功能中可见并可调整。

### 6.2 从有限上下文到相关资料检索

首版依次使用：当前对象 → 明确关联资料 → 用户允许范围内的关键词检索 → 选出相关片段。先打通来源定位，再按实测需要增加语义检索。

论文按页和片段取证，笔记按标题和段落取证。答案附来源；来源删除、内容更新后，旧结果应失效或标为过期。检索不到的答案明确说明，不能把“本次未找到”表述成“全站不存在”。

正文、提取文本、摘要和未来可能生成的向量都属于派生私有数据；落盘遵循现有加密规则，不随意新增长期明文索引。首版可使用受限范围的即时解密与内存检索，规模变大后再评估索引方案。

### 6.3 受约束的动作执行

把创建任务、建立关联、生成草稿、修改安排等封装成服务函数，由普通 UI 和 AI 共用。模型只能提出允许的结构化动作，不能直接写数据库或执行任意代码。

执行层负责字段验证、目标存在性、来源版本、幂等、冲突检测和撤销记录。已有日记建任务中的幂等与版本检查可以借鉴，但需要抽成通用能力。

默认的交互规则：

- 阅读、检索、解释：用户请求后直接运行。
- 用户明确要求新增某项记录：执行该范围内的操作，显示结果。
- AI 主动提出的安排、批量改写或改期：先呈现可编辑预览，一次应用。
- 用户手动编辑或固定的内容：后续 AI 建议尊重这些更改，不在后台覆盖。

这些是产品设计建议，不构成本轮开发的额外权限要求。

### 6.4 统一后台工作与调用预算

复用现有模型配置，在通知处理、论文全文翻译、问答、复盘之上逐步增加统一调度。

用户当前发起的问答优先，全文翻译等后台工作在可取消边界让出资源。缓存按内容版本、模型及提示版本区分；明确排队、运行、完成、失败、取消状态。

首次无需引入新队列服务或向量数据库，可从现有 SQLite、加密文件和受控后台执行器开始。缓存和队列都是实现选择，需以运行验证为准。

不能把现有某处串行翻译实现当作当前模型吞吐的实测结论；并发和限额应根据实际使用的模型服务验证后配置。

## 7. 安排能力的关键约束

AI 提出优先级、拆分和文字解释；程序检查日期、重叠、可用时长和重复条目。

当前日程已有估时字段，但估时可能缺失；自由文字时间表不能稳定表达固定课程和精确忙闲。要做可靠排程，需先补充可编辑的可用时间、固定安排和时间块关联，且不要从含糊文字推断出空闲。

四象限目前在浏览器本地。首版可以由页面显式传入用户选择的条目作为上下文；如后续迁到后端，应保留原本地数据、去重并让用户确认导入。不能假定后端已经看得到全部四象限。

## 8. 实施顺序与验收

### 第一阶段：今天做什么，做完接下来做什么

范围：全局助手入口、日程与专注上下文适配器、任务详情及轻量关联、首页今日建议、明确指令建任务、安排预览与执行。

先接通已有数据，保留原页面使用习惯。暂不把全站索引、长期偏好学习和所有生活功能作为第一阶段前置条件。

验收场景：

1. 输入“明天 15 点开会”，创建一次日程，重复请求不产生重复项；模糊的日期不会被静默补成确定日期。
2. 请求“按我今天的安排和空闲时间给个计划”，结果引用实际任务；空闲或估时不足时列出缺项，不生成看似精确的满日日程。
3. 从任务直接进入专注，能记录本次进展和关联已有笔记，刷新后仍能找到。
4. 改动或完成任务后，首页旧建议能失效；用户固定的安排保留。
5. 模型断开后仍可收集、编辑、安排和计时；失败可见且可重试。

### 第二阶段：把阅读与写作串成知识生产流程

范围：跨模块检索、论文页码与笔记段落引用、阅读问答、笔记选区操作、阅读到笔记的关联、工作周报。

验收重点：引用能定位、未覆盖内容可见、修改前能预览、原文变更后不会错误覆盖，删除的资料不会继续作为有效证据。

### 第三阶段：按需主动协助与生活学习扩展

范围：白板理解、复习题、学习计划、自然语言记账、选定相册内容整理，以及按用户设定频率生成的晨间建议和晚间草稿。

主动协助在应用运行或再次打开时触发；如果需要关机后也运行，需另外实现常驻服务或系统调度，不能把网页内定时器当作可靠的全天任务系统。

偏好可以先由用户明确设置，如单次专注长度和每天可用时间。之后再根据用户多次采纳、修改、拒绝的记录提出可编辑偏好，不凭少量行为推断个人能力或作息规律。

## 9. 怎样判断有没有真正提高效率

先记录原流程的小样本基线，再用相同任务比较，不预先承诺节省比例：

- 从粘贴通知到得到可用任务，需要多少操作与修改？
- 每天整理计划耗时多久？哪些建议被采纳、修改、撤回？
- 从打开任务到开始工作，要找多少次资料？
- 阅读材料变成带来源笔记，需要多少搬运与校对？
- 复盘引用的成果是否真实，遗漏了哪些未记录工作？

按需在本地保留操作耗时和采纳记录即可，不为评估额外上传正文。AI 生成量、聊天次数和按钮数量不作为主要成功指标。

## 10. 推荐的第一轮改动范围

优先建设 **首页今日建议 + 全局助手 + 任务详情与专注衔接**，并提供最小的上下文适配和动作执行能力。这一轮可以让用户走完“决定做什么 → 开始做 → 留下进展 → 下次继续”的完整流程。

随后把论文和笔记检索接进同一流程，再扩展复习和生活功能。每阶段都形成可使用的连续体验，再以实际节省的操作和时间决定下一轮投入。
