# Kruskal 工作台重构方案

> 需求说明与开发交接文档 · 2026-10-10  
> 目标项目：<workspace-path>/kruskal  
> 状态：需求方案，尚未据此修改代码

## 1. 要解决的问题

用户希望在网站里自由整理正在推进的事情：现在想到哪一步、准备怎么做、有哪些还没想清楚的地方。同时，用户会从 AI 对话、小红书等处得到零散想法，希望先快速记下，之后再决定是否用于某件事。

现有「科研工作台」主要按卡片、想法、代码、实验等内容类型分入口；笔记与论文另有页面。重构后的「工作台」应成为这些活动的起点，让用户能从一件正在推进的事进入相关资料，同时保留一个无需归类的随手收集入口。

### 已经由用户明确确认的需求

1. 工作台可有主事项和子事项。例如「准备会议 PPT」「推进论文」「期中考」是三个主事项；四门科目各有自己的子事项页面。
2. 工作台首页可以展开事项，并直接编辑该事项的随笔。用户同时喜欢「可反复修改的当前思路」和「按时间追加的小记」两种写法。
3. 随笔只属于工作台，用于临时想法和推进思路。它不写入「笔记·博客」。
4. 博客笔记是做事过程中形成的学习材料、整理笔记或记录；论文仍在论文库。
5. 每个事项有独立的「相关资料」链接区，用于跳转到论文和博客笔记。该区域展示链接，不复制或自动汇总资料正文。
6. 在事项里点「新建笔记」应进入现有博客编辑页；首次保存成功后，自动把该笔记的链接加入此事项的「相关资料」。
7. 工作台不要求可勾选步骤，也不使用目标、步骤、困难等固定栏目表单。
8. 日程表保持现有操作。用户自己去日程表填写 DDL 和重要节点；工作台不自动识别日期或同步任务。
9. 用户会记录自己突然想到的内容、AI 对话中的观点、刷小红书看到的有意思内容。这些内容应能先保存，无需立即归入事项。

## 2. 核心内容模型

| 内容 | 用途 | 存放位置 |
| --- | --- | --- |
| 事项 | 一件正在推进的事；可以有子事项 | 工作台 |
| 当前思路 | 对该事项现状、安排和做法的自由书写；可以反复修改 | 事项内 |
| 小记 | 带时间的短记录，保留思考与推进过程 | 事项内 |
| 随手收集 | 尚未确定归属的文字、链接和来源线索 | 工作台收集箱 |
| 相关资料 | 指向现有论文或博客笔记的链接 | 事项内 |
| 正式笔记 | 整理后的学习材料与记录 | 现有「笔记·博客」 |
| DDL、重要节点 | 有明确日期的安排 | 现有日程表，由用户手动填写 |

事项、小记和随手收集都不需要日期、优先级、任务状态等强制字段。事项只需要标题、父事项、显示顺序和基本归档能力。

### 当前思路与小记的区别

- 当前思路是一篇持续更新的自由文本，打开事项后立即能看到「现在怎么想」。
- 小记按时间追加，例如「今天和老师聊完，PPT 应先讲问题再讲实验」。旧小记保留，用户可以把重要结论手动整理进当前思路。
- 不自动从随笔中提取任务，不自动改写当前思路。

### 收集箱的定位

- 工作台顶部提供一个低门槛的「随手记」入口。用户可直接粘贴文字或 URL，再补一句自己的想法；来源名称和原链接都是可选项。
- 默认进入未归类收集箱；如果当下已知道归属，也可保存时直接选一个事项。用户可稍后把未归类内容放到某个事项、继续留在收集箱或归档。
- 收集箱支持按文字、来源或链接搜索，避免片段积累后只能翻时间线。
- 放入事项后，它作为该事项的「收集片段」出现；原始记录保留，不变成博客文章，也不自动写进当前思路。
- AI 对话先支持用户手动粘贴有价值的片段或链接；小红书先支持用户粘贴链接和自己的备注。首版不依赖第三方登录或自动抓取页面。
- 截图粘贴或上传可作为后续增强，需沿用项目的加密存储规则。

## 3. 页面与导航

### 工作台首页：/lab

侧栏「科研工作台」改名为「工作台」。/lab 不再默认跳到卡片笔记，而是打开工作台首页。

    工作台                                  ＋ 新建事项
    随手记：[输入文字或粘贴链接……]         [保存]
    收集箱：未归类的最近片段                  [查看全部]

    ▾ 准备会议 PPT
      当前思路：[在首页直接编辑的自由文本]
      小记：[写下一条新想法]  最近几条
      相关资料：[关联论文] [关联已有笔记] [新建笔记]

    ▸ 推进论文
    ▸ 期中考
        数学 · 英语 · 专业课 A · 专业课 B

首页要能直接展开并编辑事项。为避免多个长编辑器同时占据页面，首版建议一次只展开一个事项，并记住上次展开项；这是交互建议，不是用户已确认的硬性要求。收起时显示标题、当前思路的短摘要和最近更新时间。首页可手动调整事项顺序。

### 事项详情：/lab/items/:id

用于查看较长的当前思路、全部小记、收集片段、子事项和相关资料。父事项「期中考」显示四门科目的入口；每门科目有自己的当前思路、小记及资料。父事项本身也可写随笔，子事项正文不会自动合并到父事项。

### 现有科研模块

卡片、想法、代码、实验、写作资产、投稿等功能与现有数据保留，可从工作台的次级导航进入。原有 /lab/cards、/lab/ideas 等路径继续可用；不迁移或覆盖已有资料。

## 4. 相关资料与博客目录

1. 「相关资料」是明确添加的链接列表。首版支持现有论文和「笔记·博客」中的文章；用搜索选择器添加已有资料，点击后进入其原页面。
2. 工作台不因资料位于某个博客目录就自动列出整个目录。用户曾明确质疑这种自动汇总，因此不应实现为默认行为。
3. 不强制「一件事一个博客目录」。博客目录仍由用户按资料整理需要自行建立；事项与文章的关联不依赖目录路径，移动文章目录后链接仍有效。
4. 从事项点「新建笔记」时，带上来源事项 ID 打开现有 /notes/new。笔记首次创建成功后，包括自动保存首次建档的情况，只建立一次关联。用户随后可以返回来源事项。
5. 取消新建且尚未产生笔记时，不建立关联；关联失败要显示可重试提示，不能误报成功。
6. 移除相关资料链接只移除工作台入口，不删除论文或博客笔记。原资料被删除时，工作台显示「资料已删除」并允许移除失效链接。

## 5. 典型使用过程

### 准备会议 PPT

用户在首页展开「准备会议 PPT」，自由写讲述顺序、准备方法和尚未想清楚的问题。和老师交流后追加一条小记。看到一篇有用论文时，在相关资料中搜索并关联。需要整理背景材料时，从该事项点「新建笔记」，进入博客编辑页；首次保存后返回事项即可看到笔记链接。会议日期由用户在日程表中填写。

### 推进论文

当前思路记录论文主线与准备验证的判断；小记记录讨论和实验后的想法变化。相关资料提供跳往已有论文与整理笔记的入口。工作台不替代论文阅读器或博客编辑器。

### 准备期中考

「期中考」是主事项，记录总体复习思路。四科为子事项，各自维护随笔、小记、收集片段及学习材料链接。考试日期仍在现有日程表中手动填写。

### 捕捉零散内容

用户与 AI 聊天时复制一段有价值的观点，或者刷小红书时保存链接并写一句「为什么有意思」，直接丢进首页收集箱。以后可把它放入「准备会议 PPT」等事项；暂时没有对应事项时也可以继续留在收集箱。

## 6. 实现建议

以下为开发建议；具体字段和文件名应在查看当前代码后确定。

### 数据与存储

- 新增 workbench_items：ID、父事项 ID、标题、排序值、归档标记、创建与更新时间。
- 每个事项的「当前思路」使用独立正文文件，通过现有 backend/app/vault.py 加密读写；SQLite 仅保存索引元数据。
- 新增 workbench_entries：小记 ID、所属事项 ID、时间戳；小记正文同样使用 vault 加密文件。
- 新增 workbench_captures：收集片段 ID、可空的所属事项 ID、时间戳和归档标记；文字、来源与 URL 按现有加密规范保存。
- 新增 workbench_links：事项 ID、目标类型（note/paper）、目标 ID、显示顺序；同一资料可关联多个事项，同一事项内避免重复链接。
- 事项归档保留随笔、小记和链接。删除事项时不能连带删除博客、论文或其他既有模块的数据；对随笔正文应提供可恢复机制。

### 接口与前端

- 新增 /api/workbench 路由，提供事项树、当前思路、小记、收集片段、资料链接的创建、读取、编辑与归档接口。所有接口沿用现有鉴权。
- 前端新增工作台首页、事项详情和相关资料选择器；修改 frontend/src/router/index.ts 与 frontend/src/views/Lab.vue 的默认入口。
- 现有 NoteEdit.vue 接收来源事项 ID，在首次成功创建笔记后调用幂等关联接口。直接从「笔记·博客」新建的笔记保持原有流程。
- 首页当前思路需要明确的「保存中／已保存／失败」状态；切换事项、离开页面、网络失败时不得静默丢稿。小记保存成功后才清空输入框。
- 列表请求只加载摘要；展开事项后再加载完整正文和小记，避免首页同时解密和挂载所有长文编辑器。

### 兼容与边界

- 保持现有日程 API、页面和数据不变；不新增自动同步 DDL 的逻辑。
- 保持现有笔记、论文和科研模块的 ID、路由、数据格式不变。
- 新工作台正文与片段必须纳入项目现有备份、恢复和加密流程；不把明文长期放在浏览器本地存储中。
- docs/RESEARCH_WORKBENCH.md 是较早的科研模块路线图。本方案描述本轮「工作台」重构；开发时以当前代码和本轮已确认需求为准，不按旧文档重建现有模块。

## 7. 分期与验收

### 第一阶段：能在工作台理思路

完成事项树、首页展开并直接编辑、当前思路、小记、收集箱和归档。用户可以建立三个主事项及期中考四个子事项，刷新页面后内容、层级和顺序均保留；未归类的 AI 片段或小红书链接也能保存并找回。

### 第二阶段：打通资料跳转

完成搜索关联已有论文/笔记、事项中「新建笔记」后自动关联、从资料页返回来源事项，以及失效链接处理。关联和取消关联均不修改资料正文，也不自动创建博客目录。

### 验收场景

1. 在工作台首页展开「准备会议 PPT」，输入当前思路、追加小记；刷新后两种内容都在原位。
2. 新建「期中考」及四个子事项，各科可独立书写，父页面能进入四科。
3. 从 AI 对话粘贴一段文字到收集箱，稍后将它放入「推进论文」；原文与来源信息仍可查看。
4. 保存小红书链接及自己的备注，先保持未归类；之后仍可检索或从收集箱找到。
5. 给「推进论文」关联一篇已有论文；点击进入论文，再返回原事项。
6. 从「准备会议 PPT」新建博客笔记；首次保存后相关资料只出现一条链接；再次保存不重复。
7. 用户在原日程表手动填写 DDL；工作台没有自动生成日程或勾选任务。
8. 归档事项或移除资料链接后，原博客笔记、论文及其现有目录保持可用。

## 8. 留给实现时的可调整点

- 首页默认一次展开一个事项，是为性能与页面长度提出的默认方案；用户已确认的是「首页可直接展开并编辑」，尚未指定是否允许多项同时展开。
- 首版建议只在界面上提供主事项和一层子事项，满足四科场景；数据结构可保留更深层级的扩展能力。
- 收集箱首版以文字、URL 和可选来源为核心；截图粘贴或上传可在基础流程稳定后增加。
